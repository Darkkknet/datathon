# CQA — оценка качества диалогов (Freedom Broker hackathon)

Прототип Conversation Quality Analytics. Система оценивает работу оператора в чатах и звонках
(RU / KZ / EN) по настраиваемому чек-листу, показывает баллы, объяснение и реплику-доказательство,
поддерживает апелляцию и решение проверяющего с пересчётом итога.

## Запуск за 3 шага

Нужен только **Node.js 20+** (nodejs.org, версия LTS). Внешних библиотек нет, `npm install` не нужен.

1. Скопируйте `.env.example` в `.env` и вставьте ключ:
   ```
   ANTHROPIC_API_KEY=sk-ant-...
   MODEL=claude-sonnet-5-5
   DATA_API_URL=<ссылка GET организаторов без параметра &group_id=...>
   ```
   Без ключа система работает в режиме **MOCK** (заглушки вместо ИИ) — удобно, чтобы проверить интерфейс.
2. В папке проекта выполните:
   ```
   node server/index.js
   ```
   (на Mac: Терминал → `cd ~/Desktop/datathon` → команда выше; на Windows: PowerShell в папке проекта)
3. Откройте в браузере **http://localhost:3000**

Набор DEV подхватывается автоматически из `data/*.json`. Контрольный набор: на странице «Диалоги»
введите `group_id` и нажмите «Загрузить из API» (или «Загрузить JSON», если сохранили файл вручную).

## Что умеет

| Требование | Где в интерфейсе |
|---|---|
| Настройка чек-листа: критерии, формулировки, вес, тип, N/A, шкала | «Чек-лист». Каждое сохранение = новая версия |
| Оценка диалога выбранным чек-листом | Карточка диалога → «Оценить» |
| Ответ, баллы, вес, объяснение, реплика-доказательство | Карточка: блоки критериев по секциям |
| Пропущенное действие → проверенный участок | Кнопка «проверен участок №X–Y» |
| N/A с причиной, перераспределение веса | Плашка N/A, «исключён (N/A)», итог нормирован к 100 |
| Грубая ошибка отдельно | Флаг «ВЫЯВЛЕНЫ» в итогах и колонка в списке |
| Итог и результаты секций | Верх карточки |
| Переход к реплике / фрагменту звонка, плеер | Клик по «реплика №N» или ▶ у реплики звонка |
| Апелляция по критерию | «Оспорить» → комментарий |
| Решение проверяющего, пересчёт, исходная и финальная оценка | «Апелляции» → подтвердить / изменить + причина |
| Замена критерия и применение к диалогам | «Чек-лист» → правка → «Применить к диалогам набора» |
| Пакетная обработка контрольного набора | «Диалоги» → «Оценить все показанные» или `npm run eval:dev` |

## Как устроено

```
браузер (web/, Web Components)  →  сервер (server/, Node.js без зависимостей)  →  Claude API
                                          │
                                          ├─ facts.js    — факты кодом: первая реплика оператора, паузы > порога
                                          ├─ llm.js      — промпт из ТЕКУЩЕГО чек-листа, ответ через tool use, проверка, 1 повтор
                                          ├─ scoring.js  — баллы, перераспределение N/A, округление, секции (только код)
                                          └─ store.js    — хранение в storage/db.json
```

- Модель отвечает только «да / нет / N/A / ступень шкалы», объяснение и номера реплик. **Баллы считает код** —
  итог воспроизводим и проверяем (`npm test`).
- Чек-лист не зашит в код: промпт собирается из выбранной версии, поэтому новый критерий работает сразу.
- Компоненты (`<cqa-conversation-list>`, `<cqa-evaluation-card>`, `<cqa-checklist-editor>`, `<cqa-appeal-review>`)
  самостоятельные и общаются с сервером через `web/api.js` — для Dynamics 365 достаточно подключить
  компонент и задать `window.CQA_API_BASE`.

## Модель и стоимость

- Основная: **Claude Sonnet 5.5** (`claude-sonnet-5-5`), $2 / 1M входных, $10 / 1M выходных токенов.
- Дешёвый режим: **Claude Haiku 5.5** (`MODEL=claude-haiku-5-5`), $0.10 / $0.50.
- Одна оценка = 1 вызов (2 при невалидном ответе). Промпт ≈ 2–4 тыс. токенов, ответ ≈ 1–1,5 тыс.
  Оценка: **≈ $0.02 за диалог на Sonnet 5.5**, ≈ $0.001 на Haiku 5.5.
  Точная стоимость каждой оценки записывается в `usage.cost_usd` и показывается в карточке;
  итог по набору печатает `npm run eval:dev`.

## Команды

```
node server/index.js       # запуск
npm test                   # тесты расчёта итога
npm run eval:dev           # пакетная оценка набора DEV (сервер должен быть запущен)
node scripts/eval-batch.js <group_id>   # то же для контрольного набора
```

## Сценарий демо (5 минут)

1. «Диалоги» → открыть чат → показать транскрипт.
2. «Оценить» → итог, секции, обоснование → клик «реплика №N» → подсветка. Показать критерий N/A и звонок с плеером.
3. «Оспорить» критерий → «Апелляции» → изменить оценку с причиной → итог до/после.
4. «Чек-лист» → заменить критерий → «Сохранить» (новая версия) → «Применить к диалогам набора».
